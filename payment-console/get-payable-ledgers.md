# GET /api/v1/finance/payment-console/payable-ledgers

**API ID:** `finance-service.payment-console.payable-ledgers`
**Service:** erp-finance-compliance-service
**Module:** Finance
**Auth:** Required — validated via `erp_access` cookie at the gateway; no fine-grained permission beyond being an authenticated user.

## Description
**The allocation preview.** Given an amount the student wants to pay, this runs the same allocation engine [POST /payment-console/payments](./post-payment.md) will run and returns exactly which ledger lines that money would settle — including any discount and rounding lines — plus what is left over.

Call it whenever the amount, currency or date changes on the tuition tab, and show the result before the cashier commits. The preview is not a reservation: nothing is written, and the actual allocation is recomputed at POST time, so a payment made by someone else in between can change the outcome.

## Path params
None.

## Query params
All bound from the query string; `applicationGuid`, `amount`, `currencyGuid` and `payDate` are **non-optional bindings** — omit any and the request fails binding with a 400.

| Parameter | Type | Required | Notes |
|---|---|---|---|
| `applicationGuid` | Guid | **Yes** | |
| `studentGuid` | Guid | No | Nullable. As on [outstanding-ledgers](./get-outstanding-ledgers.md), supplying it lets the handler scope by the student's real academic status. |
| `amount` | decimal | **Yes** | The amount to simulate. `0` is accepted and previews an allocation of nothing. |
| `currencyGuid` | Guid | **Yes** | The currency the student is paying in. Drives the exchange-rate conversion against each ledger's own currency. |
| `payDate` | DateTime | **Yes** | Determines which day's exchange rates apply |

## Request body
None.

## Validation
None — this query has no validator. Send the same values you will POST with, or the preview will not match.

## Response 200
Returns a `PayableLedgersResultDto` as the `data` payload. See [api/README.md](../../README.md) for the envelope.

```json
{
  "success": true,
  "data": {
    "lines": [
      {
        "ledgerGuid": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
        "semesterGuid": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
        "ledgerName": "Tuition Fee",
        "ledgerNum": 1,
        "amount": 900000,
        "currencyGuid": "…",
        "currencyName": "Uganda Shilling",
        "amtDef": 900000,
        "isDiscountLine": false,
        "isRoundingLine": false
      }
    ],
    "balance": 100000
  },
  "message": null,
  "code": null,
  "errors": null
}
```

| Field | Notes |
|---|---|
| `balance` | Amount left **unallocated** — the student has overpaid relative to what is currently outstanding. On the real POST this surplus is what triggers the advance-deposit message. |
| `isDiscountLine` | The line is a discount reduction, not cash received. Present it as a deduction, not a payment. |
| `isRoundingLine` | A rounding adjustment generated by currency conversion, usually a few units |
| `amtDef` | The line's amount in the default (base) currency |

## Errors
| Status | Code | Reason |
|---|---|---|
| 400 | (binding) | A required query parameter is missing or unparseable |
| 400 | (generic failure) | `"Fee structure not assigned to this application."`, or an allocation error such as a missing exchange rate |
| 401 | `unauthorized` | Missing/invalid/expired `erp_access` cookie |
| 404 | `not_found` | `"Application not found."`, `"Currency not found."`, `"No fee structure lines found."`, or `"No outstanding ledgers found."` |
