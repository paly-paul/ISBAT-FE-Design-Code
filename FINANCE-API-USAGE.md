# Finance Module — API Usage by Page

Reverse-index of the Finance module: for every page under `src/app/finance/`, which real
backend endpoints it calls and where on the page each one is used. Generated by reading
the actual source (`src/app/finance/**/page.tsx` and the modals each page opens) — not
from the API docs themselves, so it reflects what's actually wired today, warts included.

A page marked **UI-only / mock** has no real API calls at all — everything on it is local
state or hardcoded data.

## Implemented but not used on any page

Real code exists for these, but no page currently calls them — either superseded by a
more specific endpoint, or built ahead of a page that hasn't been requested yet:

| Endpoint | Note |
|---|---|
| `GET /finance/payment-console/payments` | The raw, unfiltered tuition payments table — the docs say this isn't the way to show one student's payments (Payment Console's own history call is) |
| `GET /finance/guild/payment-guilds` | Same "raw back-office list" as above, Guild-side |
| `GET /finance/payment-ledgers` | Allocation-line join table — no page has needed it yet |
| `GET /finance/payment-others` (in `payments.ts`) | A legacy duplicate — Payment Console actually uses a different file's `/finance/other-payment` |
| `GET /finance/payment-refunds` (in `payments.ts`) | Superseded by a different file's `/finance/refund/payments` |
| `GET /finance/refund/payments` | The cross-application refund ledger — Payment Refund page scopes to one application instead |
| `GET /finance/ledger-others/dropdown` | A search-filtered picker feed — Other Ledgers lists everything and filters client-side instead |
| `GET /students/discounts/{discountGuid}/active-assignment-count` | Meant to refuse deleting a Discount while active assignments exist — not called from the Discounts page's delete flow yet |
